# How to evaluate AI visibility tools for 2027: a reproducible test for local businesses

2027 planning edition. Facts checked October 26, 2026. Recheck product capabilities and terms before purchase.

**Publisher disclosure:** Soxoa operates Soxoa, MentionedOn, Intakra and Portravo. These are practical evaluation criteria from the product team, not an independent vendor ranking.

Choose an AI visibility tool by inspecting its answers and measurement rules. Use the same buyer questions, locations and settings for each comparison, preserve the evidence and keep missing measurements separate from completed answers that omit your business.

## Plan for 2027 using evidence available today

2027 planning edition; facts checked Oct 26 2026; update before purchase. This is an evaluation method, not a prediction of next year’s rankings or a claim that any tool will make an assistant recommend you.

Start with a business decision: which services and locations need a clearer public presence, and what would you do differently after a monitoring report? A number with no next decision is another report to maintain. Select one location and one service to establish the process before expanding.

## Write the question set before choosing a dashboard

List the questions a customer might ask while choosing a provider. Include category, location and a real constraint such as availability or service type. Keep brand-name questions in a separate group: asking an assistant about your company tests a different problem from asking it to choose a provider.

Give every question an ID. Record the exact text, intended market and reason for inclusion. These are your selected test questions; do not label them measured search demand unless you have separate demand evidence. Freeze a version so later changes are visible.

- Use a manageable initial set that someone can inspect in full.
- Keep questions you expect to lose; removing them changes the test.
- When you add a location or service, create a new group rather than silently rewriting the old baseline.

## Keep an answer log someone else can inspect

For each observation, save the question ID, collection date and time, assistant or model, browsing or grounding setting, stated location context, full answer or preserved excerpt, cited URLs and collection status. Add an evidence link when the provider supports one. If a field is unavailable, record that limit instead of guessing.

Review matching by hand at first. A similarly named business, an old trading name or a link to an unrelated directory entry can produce the wrong classification. Use separate fields for a business mention and a link to the business website; they answer different questions.

## Show the denominator beside the rate

Define your own comparison sheet before looking at a vendor score. One transparent measure is completed answers naming the business divided by all completed answers in the same test group. Record planned checks, completed checks and failed checks alongside it. If nothing completed, leave the rate unavailable.

Treat unavailable surfaces and collection errors as missing measurements. Keep them visible so a good-looking rate cannot conceal poor coverage. Do not merge scores from providers with different question sets or scoring formulas and call the result a fair ranking.

- Mention rate: named completed answers / completed answers.
- Website citation rate: completed answers linking to the business site / completed answers.
- Coverage: completed checks / planned checks. Keep the raw counts next to every percentage.

## Repeat the same test before assigning credit

Choose a repeat interval you can maintain, then compare matching question IDs and settings. Mark any model, browsing, location or prompt change as a break in the series. Save a dated change log for the website or profile edits you make.

A change log makes investigation easier; it does not prove that an edit caused an answer to change. Look for repeated movement and inspect the underlying answers. Keep lead and booking measurement in your usual business systems so a visibility observation is not mistaken for a sale.

## Ask vendors to demonstrate the evidence path

Ask each vendor to show one completed answer, one failed check and one changed answer, then export the same records. Check whether a trial and paid plan use the same collection coverage. Ask what is refreshed live, what may be cached and which fields remain available after cancellation.

Use a short evaluation period to decide whether the tool reduces the work of collecting and reviewing evidence. Agree in advance who owns the weekly review and which action will follow a confirmed issue. A tool can collect observations; a person still decides whether a suggested edit is accurate and worth making.

- Can you inspect the exact question and answer behind a score?
- Are failed and unavailable checks visible in the export?
- Can you compare the same question and assistant over time?
- Does the report distinguish observations from suggested explanations?
