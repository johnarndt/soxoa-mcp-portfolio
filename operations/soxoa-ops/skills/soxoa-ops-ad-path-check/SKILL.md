# Prepare concepts and check the ad path

Use the requested product, actual offer and intended audience. Establish the platform, campaign goal and any supplied budget; never invent a spend ceiling. This skill prepares reviewable concepts and readiness evidence. It does not launch campaigns or purchase media from a drafting/audit request.

Write a useful set of distinct concepts appropriate to the task, varying the mechanism or format rather than only wording. For each, state audience, visual idea, hook, copy, call to action, landing destination and the reasoning labeled as judgment. Use real current product claims and label illustrative examples. Do not fabricate testimonials, metrics, screenshots or customer results.

Verify current targeting controls and ad rules through official platform sources when browsing is available. Recommend only supported options, distinguish proposals from configured ad sets, and mark unverified settings when access is unavailable. A hypothetical audience is not an installed pixel, customer list or retargeting segment.

Audit each material landing path using authorized public screens or a supplied export. On desktop and phone-width views, inspect promise continuity, redirects, meaningful query parameters, required form fields, errors, trial/payment terms and the next step. Browser behavior and analytics receipt are separate checks; a preserved URL does not prove an event was received.

Account creation, owner emails, form submission, test payments and analytics/audience mutations require the actual task’s test authorization and access. Use designated test identities and verified test mode. Do not assume a public checkout is in test mode, enter real card details or initiate a live charge to satisfy an audit. Without access, mark those steps untested and give a bounded manual verification step.

Where authorized test tools exist, check a normal signup, error/decline behavior, exactly-once conversion identity/value and the intended exclusion rules. Do not claim a test passed from the visible form alone. Preserve evidence of failure and uncertainty, including steps blocked by missing accounts, tools or instrumentation.

Return concepts and a pass/fail/untested readiness table with date, scope, actual observations and concrete fixes. Rank blockers by effect on the user’s proposed campaign. A proposed fix is not applied; an accepted limitation is not a passing check. Implement changes, publish ads or start spend only within a separate or already explicit authorization.
