# Write an evidence-based work brief

Use the requested period and timezone; infer a normal daily or weekly window from clear context and state it. Read only repositories, reports, work records or agent-session exports the user supplied or authorized. This skill has no built-in access to private transcripts, hidden directories, other chats, a CRM or a mail account.

Where tools permit, inspect relevant commits, diffs and retained verification receipts within that scope. A session request records an intention, not proof the work was done. Use authorized session exports or a host’s supported read API; never assume a particular agent’s local transcript path exists or scan every local profile. If a source is missing, produce the supported brief and name the coverage gap.

Select evidence by materiality and the requested window. Keep source IDs and timestamps, note truncation, and retain unresolved promises rather than letting a long diff displace them. Do not quote tokens, credentials or private customer details. If an actual exposed credential is discovered, record a redacted follow-up with its source and the user’s applicable response process; do not rotate unrelated credentials automatically.

Distinguish discussed, changed, tested, merged, deployed and independently verified states. Do not call every merged commit shipped; use actual release evidence. For each product or workstream, explain what moved, the consequence, remaining work and an accountable next decision. Preserve conflicting evidence rather than forcing a single success story.

Return a short narrative followed by the useful open threads. Add content ideas or metrics only when requested or helpful and supported. Link claims to the actual record. With no usable records, offer a fill-in brief or request the source that matters; do not manufacture activity from memory.

If the user asks for a recurring brief, use an available supported automation tool and its documented source permissions, destination and schedule. A prepared schedule is not an installed automation. Without that tool, return a concrete setup specification or manual routine and its dependencies. Do not install a background job, start paid model calls or send email merely because a one-time brief was requested.
